אנדרואיד לא מוצא כתובת + הודעת שגיאה מפורטת מ-Gemini
**הבעיה של האנדרואיד**: המשתמש חיבר את הטלפון לאותה רשת, הקליד את ה-URL עם הפורט, וקיבל "כתובת לא נמצאה". כל הטלפונים שלו שעבד עליהם הצליחו לפתוח (iPhone), Android כולם נכשלו.

**מה זה אומר**: הטלפון באמת לא מצליח להגיע ל-IP שאני מציג. **לא** קשור ל-HTTPS-cleartext (שגיאה אחרת לגמרי).

**שורש הבעיה**: `get_lan_ip()` שלי החזיר רק **כתובת אחת** — זאת של ה-default route. אם למכשיר של Kodi יש **יותר ממסך אחד** (Android TV עם WiFi+Ethernet, מחשב נייד עם WiFi+VPN, PC עם Docker bridge), ה-IP היחיד שזיהינו יכול להיות ב-subnet שונה ממה שהטלפון רואה. הטלפון מנסה להגיע אליו → נכשל → "כתובת לא נמצאה".

**התיקון:** `gemini_pair` עכשיו מזהה את **כל** ה-LAN IPv4 שיש במכשיר:
1. הטריק של "התחבר ל-8.8.8.8" (default route)
2. **`ip -4 addr` / `ifconfig` דרך subprocess** — חדש, תופס interfaces שאינם default route (Android תומך)
3. Probes לכל טווח פרטי (10.x, 192.168.x, 172.16-31.x, 100.64-127.x)
4. Hostname lookup

כל התוצאות מסוננות דרך `_is_private_lan_ip()` (RFC 1918 + 100.64/10) אז IPs של VPN/אינטרנט לא נכנסים.

**בדיאלוג ב-Kodi**: עכשיו מציג **כל הכתובות שזוהו**. עם יותר מ-interface אחד, רואים:
```
מטלפון אחר ב-WiFi (נסה כל אחת עד שאחת תיפתח):
   • http://10.0.0.5:8765
   • http://192.168.1.10:8765
מאותו מכשיר: http://localhost:8765
```

**בנוסף — הודעת שגיאה מפורטת מ-Gemini**: כש-Google מחזיר 400/403, `gemini.test_key()` עכשיו מפענח את ה-JSON `error.message` (לדוגמה "API key not valid. Please pass a valid API key." או "Daily quota exceeded") ומציג ב-Kodi. עד עכשיו ראינו רק "rejected by Gemini (400)" בלי לדעת **למה**.

**טקסט troubleshooting בדיאלוג**: הוספתי 2 הסברים קצרים:
- Chrome אנדרואיד לא נפתח? תיקון של הגדרת "Always use secure connections", או נסה Firefox/Brave/Samsung Internet
- אייפון מקבל 400? השווה את ה-fingerprint למפתח ב-AI Studio; אם תואם — המפתח עצמו לא תקין, צור חדש

**Fingerprint הורחב** מ-4 ראשונים+4 אחרונים ל-**8+8** — קל יותר לוודא ויזואלית בלי לחשוף את האמצע.
